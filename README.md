# 《膜拜 Siyuan》全剧情、数值公式、科技树与通关攻略——源码解析版

(已找到公开源码仓库)

**游戏地址：** [膜拜 Siyuan](https://lmoliver.github.io/mosiyuan/)

**源码仓库：** [LMOliver/mosiyuan](https://github.com/LMOliver/mosiyuan)

**分析版本：** `0.6.4.2`，以 GitHub `master` 分支公开源码为依据。([github.com][1], [raw.githubusercontent.com][2])

这款游戏并不是传统的多选项文字冒险，而是一个拥有世界观、文明重建、科技树、资源生产、实验谜题和战争系统的**增量经营游戏（Incremental Game）**。

它的剧情主要通过新区域的解锁、区域介绍、科技说明、实验反馈和战斗玩法展开。必须区分三种内容：

* **已实装剧情：** 有明确文本、可以通过正常游戏机制触发。
* **背景与隐含叙事：** 世界设定存在于代码中，但没有独立演出的剧情。
* **未完成内容：** 已定义名称或部分函数，却没有实现完整玩法，不应虚构结局。

下面按照实际游戏推进顺序讲解，再拆解底层公式。所有涉及等级的购买公式，默认使用**购买前的当前等级或当前持有数量**，而不是购买后的数值。

## 第一篇：完整世界观与主线推进

### 第一章：文明毁灭后的荒野

剧情区域 01 · 荒野

游戏开场的世界曾拥有高度发达的文明。这个文明的力量来自三个互相关联的体系：科技、魔法和信仰。居民相信 Siyuan 是最强大的神明，也是他们文明繁荣的核心。

但一次失控的魔法实验破坏了支撑世界的真理体系。科技与魔法迅速崩塌，灾难席卷星球，城市、建筑、法阵与宗教雕像纷纷毁灭。

唯独信仰没有彻底消亡。幸存者仍相信 Siyuan 未曾抛弃他们，因此文明复兴从最简单的行动开始：膜拜。

**游戏目标：** 从零积累膜拜次数，吸引信徒，建立教堂，重新组织社会。

**这一章节的核心玩法：** 膜拜 → 真诚膜拜 → 信徒 → 教堂 → 信仰 → 经书 → 传教。

### 第二章：遗迹中的三条知识之路

剧情区域 02 · 遗迹

当文明重新积累人力与信仰后，幸存者开始探索地下遗迹。发掘远古遗迹既昂贵又危险，但他们已经不能继续停留在原地。

在遗迹中，人们发现了请求水晶的方法。水晶成为复兴科技与魔法的关键材料，也推动了三条发展路径：

**智慧 → 朝圣地 → 宝石 → 神坛 → 神学**

代表宗教体系的重建，依靠宝石与神坛形成神学产能。

**奥秘 → 炼金区 → 魔法石 → 魔法师 → 魔力**

代表魔法体系的复兴，魔法石在魔法师的作用下转变为魔力。

**本质 → 实验室 → 透镜 → 科学家 → 研究**

代表科技体系的复兴，通过透镜、科学家及研究产出重新认识自然规律。

这三条路线并非互斥分支，而是需要共同发展的资源体系。之后的真理实验将同时消耗宝石、魔法石、透镜和三种体系的资源。

### 第三章：城镇与真理之路

剧情区域 03 · 城镇

遗迹探索带来的知识令幸存者逐渐摆脱愚昧。然而，新兴城镇依旧面临灾难、战争以及科技发展带来的风险。

为了不再重演文明毁灭的历史，人们必须重新认识被打碎的真理。

这时游戏进入重要的阶段：**追寻真理**。

玩家必须反复进行三材料实验，猜中隐藏的正确配比，完成多个实验阶段，才能获得更高层次的真理。

每次突破真理等级，不仅象征着文明在理解宇宙方面前进了一步，也会开放新的科技研究。

已实装的真理实验谜题共有五个层级，由不同的反馈规则组成。后文会分别解释它们的数学原理、尝试次数、价格惩罚和推理策略。

### 第四章：外域与文明战争

剧情区域 04 · 外域

科技发展到一定程度后，人们认识到这个星球并非只有一个文明。

远方还存在其他文明。这些文明是否仍信仰 Siyuan，尚无确切答案。

幸存者不再满足于城镇中的和平发展，而是希望通过探索、战争和资源争夺扩大自身的力量。

从这一阶段开始，游戏引入：

* 元素塔和元素资源生产；
* 光明值；
* 战意与战争等级；
* 入侵敌人及其属性、遗传和进化；
* 建造时间不同的防御工事；
* 消灭敌人以获得魔元素；
* 魔灵树、时间感应和世界加速。

这里标志着游戏从纯粹的资源经营转为带有塔防、敌人演化和速度控制的复合系统。

以上四个区域的叙事均可以在 `ui.html` 的正式界面定义中直接核对。([raw.githubusercontent.com][3])

### 第五章：工业基地与未完成的未来

剧情区域 05 · 基地

外域之后还有一个容易遗漏的第五区域——**基地**。

玩家研究出魔灵树科技后，可以开辟工业生产基地。基地被用于测试新的资源生产方式，但实验本身与敌人入侵都可能造成危险。游戏设定中，Siyuan 的庇护使基地不会被彻底摧毁。

现有界面允许购买魔灵树树苗，但明确显示“尚未实装”。这意味着魔灵树的完整种植、成长、收获和后续工业生产尚未形成可验证的完整系统。([raw.githubusercontent.com][3], [raw.githubusercontent.com][3])

因此，**目前能够确认的主线是文明重建、探寻真理、外域战争，再延伸到尚未完成的工业基地**。不能把源代码中缺失的最终战争、终极真理、文明飞升等情节写成官方结局。

## 第二篇：基础资源经济系统——全部主要公式

为了让公式能够直接用于计算，统一约定：

| 符号                                  | 含义                 |
| ----------------------------------- | ------------------ |
| \(M\)                               | 当前剩余膜拜次数 `moValue` |
| \(C\)                               | 累计点击次数 `moCount`   |
| \(a\)                               | 真诚膜拜等级             |
| \(f\)                               | 当前信徒数量             |
| \(h\)                               | 当前教堂数量             |
| \(X\)                               | 当前信仰               |
| \(b\)                               | 经书数量               |
| \(p\)                               | 传教等级               |
| \(r\)                               | 遗迹数量               |
| \(T\)                               | 当前真理等级             |
| \(W,U,N\)                           | 智慧、奥秘、本质等级         |
| \(q\)                               | 水晶数量               |
| \(g,m,\ell\)                        | 宝石、魔法石、透镜数量        |
| \(k_i\)                             | 对应科技当前等级           |
| \(\lfloor x\rfloor,\lceil x\rceil\) | 向下、向上取整            |

### 1. 真诚膜拜

每次购买真诚膜拜：

* 真诚膜拜等级 +1；
* 扣除相应膜拜次数；
* 不扣除累计点击数。

价格为：

$$
P_{\text{真诚}}=
\left\lfloor10\left(1+\frac{0.2}{h+1}+
\frac{0.1}{\sqrt{U+1}}\right)^a\right\rfloor
$$

初期没有教堂与奥秘等级时：

$$
P_{\text{真诚}}=\lfloor10(1.3)^a\rfloor
$$

游戏在累计点击达到 10 次后显示购买按钮。

### 2. 每次膜拜的实际收益

$$
\boxed{
\Delta M=\left\lceil
(1+a)(1+f)(1+W)D
\right\rceil
}
$$

其中 \(D\) 是虔诚感应倍率，未获得虔诚感应时通常为 1。

这一公式说明真诚膜拜、信徒和智慧等级是相乘关系，而非简单相加。

假设：

* 真诚膜拜 20 级；
* 10 位信徒；
* 智慧 5 级；
* 感应倍率为 1；

则一次膜拜获得：

$$
(1+20)(1+10)(1+5)=1386
$$

次膜拜资源。

### 3. 购买信徒的价格

$$
\boxed{
P_{\text{信徒}}=
\left\lceil
\max\left(
100\cdot1.6^{\frac{f}{(1+0.15p)F_{\text{整洁}}}}
\left(\frac{1000}{1000+X(1+N)}\right)^{2.5},
f^2
\right)
\right\rceil
}
$$

这里的 \(F_{\text{整洁}}\) 是整洁科技产生的修正倍率。

三个关键特点：

1. 信徒越多，下一次购买越贵。
2. 传教等级越高，价格增长速度越慢。
3. 信仰和本质等级能够压低第一部分费用，但不能突破 \(f^2\) 的价格下限。

而且源码规定，每次购买实际获得：

$$
\Delta f=1+7\min(k_{\text{法术}},5)
$$

即法术科技达到 5 级时，一次购买可以增加 36 位信徒。

**特别注意：** 传教本身并不直接发放信徒，而是通过传教等级降低购买信徒的价格增长速度。

### 4. 教堂价格

$$
P_{\text{教堂}}=
\left\lceil5+h^{1.1+\frac{0.1}{1+F_{\text{巨石}}}}\right\rceil
$$

其中：

$$
F_{\text{巨石}}=(1+H)\sqrt{1+k_{\text{巨石}}}
$$

\(H\) 为持有的巨石数量。

购买教堂消耗的是**信徒**，不是膜拜资源。投入建造的信徒会从当前数量中扣除。

### 5. 信仰转换

$$
\boxed{
\Delta X=
\frac{M}{2000}\cdot h(1+W)
\left(1+\frac{k_{\text{聚焦}}}{4}\right)
}
$$

执行转换后：

$$
X'=X+\Delta X,\qquad M'=0
$$

也就是说，信仰转换会清空当前膜拜资源，但不会把真诚膜拜等级、点击次数或信徒清零。

### 6. 经书价格与自动膜拜

经书价格：

$$
P_{\text{经书}}=
100\cdot1.15^{\frac{b}{1+K/2}}
$$

\(K\) 是知识之书数量。

经书提供的自动点击量：

$$
A_{\text{自动}}=
\min(C/1000,1)
+\left\lfloor1.2b(1+U)^{1.5}\right\rfloor
$$

每秒额外增加的膜拜资源，忽略世界加速时约为：

$$
\frac{dM}{dt}=A_{\text{自动}}\Delta M
$$

源码还会将自动点击计入累计点击次数，因此自动点击本身也能推动点击里程碑。

### 7. 传教

从当前传教等级 \(p\) 开始一次传教：

$$
P_{\text{传教}}=\lceil10(1.6)^p\rceil
$$

消耗经书。

需要连续答对：

$$
N_{\text{答题}}=3p+5
$$

道问题才可升级。错题会直接导致本轮失败，已经支付的经书不会自动退还。

| 当前传教等级 | 经书费用 | 连续正确题数 |
| ------ | ---- | ------ |
| 0      | 10   | 5      |
| 1      | 16   | 8      |
| 2      | 26   | 11     |
| 3      | 41   | 14     |
| 4      | 66   | 17     |
| 5      | 105  | 20     |

这些公式对应 `mosiyuan.js` 的点击、建筑、信仰、经书和传教计算部分。([raw.githubusercontent.com][2], [raw.githubusercontent.com][2], [raw.githubusercontent.com][2])

## 第三篇：遗迹、神学、魔法与科研的完整公式

### 1. 探索遗迹

探索下一个遗迹需要的信徒数：

$$
F_{\text{需要}}=100+10r
$$

消耗的信仰：

$$
\boxed{P_{\text{遗迹}}=5\times10^6\cdot2^{1.8^r}}
$$

| 已探索遗迹数 | 下一遗迹需要信徒 | 信仰花费          |
| ------ | -------- | ------------- |
| 0      | 100      | 10,000,000    |
| 1      | 110      | 约 17,411,011  |
| 2      | 120      | 约 47,200,000  |
| 3      | 130      | 约 284,000,000 |
| 4      | 140      | 约 5.18×10⁹    |

该价格是双层指数增长，因此后期探索成本很高。

遗迹数量还会降低水晶请求的增长速度。

### 2. 祈求恩赐（水晶）

$$
\boxed{
P_{\text{祈求}}=
\frac{10^{10}\cdot1.6^{q/[r(1+T)]}}{X^{1/3}}
}
$$

每次请求水晶时，实际获得：

$$
\Delta q=1+7\min(k_{\text{光学}},5)
$$

最高一次 36 水晶。

关键技巧是保持较高信仰。信仰越高，所需膜拜次数越低；不过请求水晶不会消耗信仰，而是消耗膜拜次数。

例如当 \(q=0\)、\(X=10^9\) 时：

$$
P_{\text{祈求}}=\frac{10^{10}}{1000}=10^7
$$

当前持有的水晶越多，下一次祈求也越贵，所以不需要把水晶无限囤积。

### 3. 三项遗迹研究

**智慧升级：**

$$
P_W=
\left\lceil
\frac{\left(W/(1+T)+1.5\right)^2}{1+A/3}
\right\rceil
$$

\(A\) 为神坛数量。

**奥秘升级：**

$$
P_U=
\left\lceil
\frac{\left(U/(1+T)+4.5\right)^3}
{W(1+G/3)}
\right\rceil
$$

\(G\) 为魔法师数量。

**本质升级：**

$$
P_N=
\left\lceil
\frac{\left(N/(1+T)+4.5\right)^3}
{U(1+S/3)}
\right\rceil
$$

\(S\) 为科学家数量。

三项研究都消耗水晶。奥秘受到智慧等级制约，本质受到奥秘等级制约。

### 4. 水晶加工成三种材料

宝石产量：

$$
\Delta g=
\max\left(0,\left\lfloor
\frac{qW}{18}-0.6g
\right\rfloor\right)
$$

魔法石产量：

$$
\Delta m=
\max\left(0,\left\lfloor
\frac{qU}{18}-0.6m
\right\rfloor\right)
$$

透镜产量：

$$
\Delta\ell=
\max\left(0,\left\lfloor
\frac{qN}{18}-0.6\ell
\right\rfloor\right)
$$

点击雕琢、赋能或打磨后，相应材料增加计算得到的数量，**当前水晶全部清零**。

这是一个很重要的资源陷阱：三项加工共用同一份水晶库存。

例如拥有 900 水晶、智慧 6 级、没有宝石时，点击雕琢得到：

$$
\Delta g=\lfloor900\times6/18\rfloor=300
$$

随后水晶归零。必须重新祈求恩赐，才能进行另外两种加工。

### 5. 神坛、魔法师和科学家的购买价格

这三种设施共享相同的指数价格结构：

$$
P_{\text{神坛}}=16(1.5)^A
$$

$$
P_{\text{魔法师}}=16(1.5)^G
$$

$$
P_{\text{科学家}}=16(1.5)^S
$$

分别消耗宝石、魔法石、透镜。

前几个等级的价格为：

| 当前数量 | 购买下一个所需材料 |
| ---- | --------- |
| 0    | 16        |
| 1    | 24        |
| 2    | 36        |
| 3    | 54        |
| 4    | 81        |
| 5    | 121.5     |

源码没有对价格统一向上取整，界面中的简化显示值不代表实际判定没有小数。

### 6. 神学每秒产量

$$
R_{\text{神学}}=
\frac{
\max\left(
0,\sqrt{\Delta M\cdot g}
-\frac{1+\mathrm{theology}}{A}
\right)
}{10^4}
(1+k_{\text{眼镜}})
$$

其中 `theology` 是当前神学总量，而非神学等级。

神学生产有一个负反馈项：

$$
-\frac{1+\mathrm{theology}}{A}
$$

因此神学越多，净生产速度可能越低；增加神坛可以缓解这一限制。

没有神坛时，不能形成有效的神学产能。

### 7. 魔力生产

魔法石的理论消耗速度：

$$
R_{\text{魔法石消耗}}=
\frac{\max(0.01,m/500)\sqrt G}
{F_{\text{法阵}}}
$$

转化倍率：

$$
R_{\text{魔力倍率}}=
5G\left(1+\frac{k_{\text{放大镜}}}{4}\right)
F_{\text{法阵}}
$$

其中：

$$
F_{\text{法阵}}=(1+Z)\sqrt{1+k_{\text{法阵}}}
$$

\(Z\) 是已拥有的法阵数量。

一个长度为 \(s\) 秒的实际游戏更新周期内：

$$
c=\min(m,sR_{\text{魔法石消耗}})
$$

$$
m'=m-c
$$

$$
\mathrm{magic}'=\mathrm{magic}
+cR_{\text{魔力倍率}}
$$

注意法阵同时降低魔法石消耗速度和提高转化倍率。这是一种提高原料利用效率的机制，但如果魔法石供应充足，单位时间的总产量并不会因为这两个因子相乘而无条件同步提升。

### 8. 科研产出与容量

每秒研究产量：

$$
R_{\text{研究}}=
\frac{\sqrt{\ell S}}{2}
\sqrt{1+k_{\text{眼镜}}}
\left(1+\frac{\sqrt{k_{\text{科普}}}}{4}\right)
$$

研究容量上限：

$$
\boxed{
L_{\text{研究}}=
50S^2(1+k_{\text{眼镜}})
\left(1+\frac{\sqrt{k_{\text{科普}}}}{4}\right)
}
$$

更新规律：

$$
\mathrm{science}'=
\min\left(
L_{\text{研究}},
\mathrm{science}+sR_{\text{研究}}
\right)
$$

**攻略意义：** 科学家数量不仅影响产量，而且以平方速度提高研究容量。真理实验或科技研究的价格超过容量上限时，单纯等待没有用，必须先提高研究容量。

### 9. 巨石、法阵、知识之书与元素塔

| 项目     | 购买价格公式                                         | 消耗资源 |
| ------ | ---------------------------------------------- | ---- |
| 巨石     | \(10^{18}\cdot2.5^H\cdot0.97^{k_{\text{巨石}}}\) | 信仰   |
| 法阵     | \(3(Z+1)^2\)                                   | 巨石   |
| 知识之书   | \(2+K\)                                        | 法阵   |
| 元素塔·巨石 | \(3+\lfloor2E\rfloor\)                         | 巨石   |
| 元素塔·法阵 | \(1+\lfloor E/4\rfloor\)                       | 法阵   |
| 元素塔·透镜 | \(100\cdot4^E\)                                | 透镜   |

\(E\) 为现有元素塔数量。

因此第一座元素塔需要 3 巨石、1 法阵、100 透镜；第二座需要 5 巨石、1 法阵、400 透镜。

以上公式来自主脚本的计算属性与资源操作函数。

## 第四篇：真理 I～V 的五大实验与全部花费

这是游戏最值得研究的核心机制。

### 1. 真理实验的共同规则

每轮实验中，系统随机产生一个秘密三元组：

$$
(t_x,t_y,t_z)
$$

玩家提交：

$$
(x,y,z)
$$

分别代表投入的宝石、魔法石和透镜数量。

实验后会给出反馈，不同真理等级采用不同的数学函数。必须三个值全部与秘密值一致才算成功。接近正确答案并不够。

每个真理等级又需要连续完成指定数量的独立实验阶段。

真理实验阶段总览

| 目标 | 材料范围 | 阶段 | 正常尝试数/阶段 |
| -- | ---- | -- | -------- |

注：正常尝试数是开始出现价格加速惩罚前的次数，并不是绝对禁止继续尝试的上限。

### 2. 真理 I：曼哈顿距离

当前真理等级 \(T=0\)。

$$
\boxed{
d=|x-t_x|+|y-t_y|+|z-t_z|
}
$$

反馈显示为差距 \(d\)。

例如目标为：

$$
(20,30,40)
$$

猜测：

$$
(22,27,45)
$$

得到：

$$
d=2+3+5=10
$$

此题适合利用多次实验构造线性关系。固定其中两个变量，改变第三个变量，就可以观察距离变化。

可以用区间与绝对值约束缩小候选空间，而不是逐个穷举三维组合。

### 3. 真理 II：欧几里得距离

当前真理等级 \(T=1\)。

$$
\boxed{
d=\operatorname{round}
\left(
\sqrt{(x-t_x)^2+(y-t_y)^2+(z-t_z)^2}
\right)
}
$$

与真理 I 不同，三个坐标偏差的平方共同决定结果。

理想情况下，可以围绕几个不同方向的点进行测量，然后利用三维距离约束确定目标。

需要注意这里是 `Math.round` 后的整数距离，存在四舍五入误差。若返回 \(d\)，则实际距离通常落在：

$$
d-0.5\leq d_{\text{真实}}<d+0.5
$$

的范围内。

### 4. 真理 III：材料过量数量

当前真理等级 \(T=2\)。

反馈只说明有多少种材料投入过多：

$$
\boxed{
d=[x>t_x]+[y>t_y]+[z>t_z]
}
$$

方括号内条件成立取 1，不成立取 0。

例如反馈“2 种材料过多”，仅说明三个坐标中恰好有两个高于目标，但不会直接告诉玩家是哪两个。

这使真理 III 变成了一个组合搜索问题，需要使用对照实验、极端取值和排除法。

### 5. 真理 IV：相位异或

当前真理等级 \(T=3\)。

定义：

$$
d_x=|x-t_x|,\quad
d_y=|y-t_y|,\quad
d_z=|z-t_z|
$$

则：

$$
\boxed{
\text{相位}=1+\left((d_x\oplus d_y\oplus d_z)\bmod9\right)
}
$$

其中 \(\oplus\) 是整数按位异或。

异或反馈不像几何距离那样随位置接近而单调变化。因此简单的“往反馈数值变小的方向搜索”是不正确的。

此关更适合计算机辅助枚举：维护所有可能的目标三元组，根据相位结果持续过滤候选集合。

### 6. 真理 V：最大偏差坐标

当前真理等级 \(T=4\)。

先计算：

$$
d_{\max}=\max(d_x,d_y,d_z)
$$

反馈编码为：

$$
r=[d_x=d_{\max}]
+2[d_y=d_{\max}]
+4[d_z=d_{\max}]
$$

| 返回值 | 代表含义       |
| --- | ---------- |
| 1   | 宝石偏差最大     |
| 2   | 魔法石偏差最大    |
| 3   | 宝石与魔法石并列最大 |
| 4   | 透镜偏差最大     |
| 5   | 宝石与透镜并列最大  |
| 6   | 魔法石与透镜并列最大 |
| 7   | 三种偏差完全相同   |

这关的反馈不是直接距离，而是描述哪个维度偏离目标最严重。

### 7. 真理实验的全部资源花费

设：

* \(T\)：当前真理等级；
* \(x,y,z\)：本次投入的宝石、魔法石、透镜；
* \(n\)：本阶段已尝试次数；
* \(A_T\)：当前真理等级的正常尝试次数；
* \(K\)：知识之书数量；
* \(k_d\)：毒奶科技等级；
* \(k_w\)：流水术等级。

首先计算超次惩罚因子：

$$
\boxed{
F_{\text{次数}}=
\max\left(1,3.5^{n-A_T+1}\right)
}
$$

随后有四种附加资源费用。

**水晶：**

$$
\boxed{
P_{\text{水晶}}=
\left\lceil
F_{\text{次数}}\cdot2.5^T(x+y+z)
\frac{2}{3+\sqrt{k_d}}
\cdot0.8^K
\right\rceil
}
$$

**神学：**

$$
P_{\text{神学}}=
\frac{16x\cdot6^TF_{\text{次数}}}
{1+k_w/20}
$$

**魔力：**

$$
P_{\text{魔力}}=
\frac{36y\cdot6^TF_{\text{次数}}}
{1+k_w/16}
$$

**研究：**

$$
P_{\text{研究}}=
\frac{49z\cdot6^TF_{\text{次数}}}
{1+k_w/8}
$$

每次实验总共实际扣除七类资源：投入的 \(x\) 宝石、\(y\) 魔法石、\(z\) 透镜，加上水晶、神学、魔力、研究四项费用。

### 8. 为什么尝试次数非常重要

假设某关正常可以尝试 5 次。

| 下一次实验 | 已尝试 \(n\) | 费用倍率   |
| ----- | --------- | ------ |
| 第 1 次 | 0         | 1      |
| 第 5 次 | 4         | 1      |
| 第 6 次 | 5         | 3.5    |
| 第 7 次 | 6         | 12.25  |

## 第六篇：外域战斗、元素与防御系统

### 1. 元素生产

基本元素共有四种：水、火、土、风。

拥有 \(E\) 座元素塔时，每种基本元素的生产速度为：

$$
R_{\text{基本元素}}=0.001E
$$

单位为元素数量/游戏秒。

因此 10 座元素塔每秒生产：

$$
0.001\times10=0.01
$$

单位的水元素，同时火、土、风也各获得 0.01 单位。

游戏还定义了谬、乱、虚、魔、冰、气、雨、木、炭等元素，但并不是每一种都已经拥有完整获取或消费渠道。

### 2. 光明值

光明初始为 1，表示 100%。

光明自然恢复：

$$
L'=\min\left(1,L+\frac{s}{3600}\cdot0.001E\right)
$$

这里 \(s\) 是经过世界速度修正的游戏秒数。

换成每小时的游戏时间，每座元素塔能够恢复 0.001 单位光明，即 0.1 个百分点。

光明对于抵御敌人非常重要。当敌人突破防御到达距离 0 的位置，就会对光明值造成损失。

### 3. 阵地容量

$$
\boxed{
P_{\text{阵地}}=\lceil\min(3E,15)\rceil
}
$$

即：

| 元素塔数量 | 最大防御建筑数 |
| ----- | ------- |
| 0     | 0       |
| 1     | 3       |
| 2     | 6       |
| 3     | 9       |
| 4     | 12      |
| 5 或更多 | 15      |

防御工事的数量存在 15 座上限，不会随着元素塔无限增长。

### 4. 五种防御工事的成本及伤害

**水箭塔**

建造花费：1 法阵、5 巨石、2 水元素。

前置：流水术≥3，已经发现水元素。建造时间 20 游戏秒。

每次攻击的基础魔法伤害 0.1，冷却 0.8 秒。运行消耗水元素 0.01/秒。

---

**火焰陷阱**

建造花费：1 法阵、5 巨石、5 火元素。

前置：烈焰阵≥3，已经发现火元素。建造时间 30 游戏秒。

基础物理伤害 0.3/秒，无固定攻击冷却。运行消耗火元素 0.01/秒。

---

**疾风阵**

建造花费：1 法阵、5 巨石、7 风元素、7 土元素。

前置：疾风阵科技≥1，风语术≥5，已经发现风与土元素。建造时间 40 游戏秒。

每次击退敌人 0.15 距离，冷却 1 秒。运行消耗风、土元素各 0.01/秒。

---

**咕咕阵**

建造花费：1 法阵、5 巨石、15 风元素。

前置：疾风阵科技≥1，御鸟术≥5，已经发现风与土元素。建造时间 45 游戏秒。

基础精神伤害：

$$
\frac{1}{2+d}\quad \text{每游戏秒}
$$

\(d\) 为敌人当前距离。运行消耗风、土元素各 0.02/秒。

**纯魔巨炮**

建造花费：1,000,000 魔力、2 法阵、30 魔元素。

前置：法阵科技≥5，已经发现魔元素。建造时间 60 游戏秒。

每次基础魔法伤害 15，冷却随机在 40～60 秒之间。运行消耗水、火、土、风、魔元素各 0.01/秒。

以上是建造时扣除的固定资源与运行成本；建造价格不随同类建筑现有数量变化。([raw.githubusercontent.com][2])

### 5. 防御计算公式

定义攻击类型对应的防御值为 \(D\)，攻击的基础伤害为 \(v\)，穿透强度为 \(p\)。

源码的实际伤害公式为：

$$
\boxed{
\mathrm{damage}=
v\min\left(1,\frac{p}{p+D}\right)
}
$$

其中敌人防御分为三种：

* `defendx`：精神相关防御；
* `defendy`：魔法相关防御；
* `defendz`：物理相关防御。

水箭塔每次攻击：

$$
d_{\text{水箭}}=
0.1\min\left(1,\frac{0.1}{0.1+D_y}\right)
$$

火焰陷阱在 \(s\) 游戏秒内：

$$
d_{\text{火焰}}=
0.3s\min\left(1,\frac{0.3}{0.3+D_z}\right)
$$

咕咕阵在 \(s\) 游戏秒内：

$$
d_{\text{咕咕}}=
\frac{s}{2+d}
\min\left(1,
\frac{1/(2+d)}{1/(2+d)+D_x}
\right)
$$

纯魔巨炮每次攻击：

$$
d_{\text{巨炮}}=
15\min\left(1,\frac{15}{15+D_y}\right)
$$

疾风阵不直接造成血量伤害，而是改变位置：

$$
d'=d+0.15
$$

并减少敌人用于进化评价的功勋：

$$
\mathrm{score}'=
\mathrm{score}-\frac{0.15}{\mathrm{strength}}
$$

### 6. 敌人的生成、移动与光明破坏

敌人内部具有六维属性：

$$
\mathbf v=
(\text{攻击},\text{精神防御},\text{魔法防御},
\text{物理防御},\text{速度},\text{生命})
$$

通过基因产生初始属性后，会按实力值 \(S_e\) 对六维向量归一化：

$$
\boxed{
v_i'=\frac{S_e v_i}{\sqrt{\sum_{j=1}^6v_j^2}}
}
$$

敌人出生位置固定为距离 10。

若其速度为 \(v\)，经过 \(s\) 游戏秒：

$$
d'=\max(0,d-vs)
$$

敌人到达位置 0 后，尚未消耗的移动时间会用于攻击光明。

设实际攻击持续时间为 \(t\)，攻击属性为 \(a_e\)：

$$
\mathrm{damage}_{\text{光明}}=a_et
$$

$$
L'=\max\left(0,L-\frac{a_et}{10000}\right)
$$

这说明敌人的高攻击值只有在成功突破防线后才会直接威胁光明。

### 7. 战意与战争等级

点击“战意”可获得：

$$
\Delta B=10k_{\text{战意感应}}^2
$$

战意每游戏秒的衰减速度约为：

$$
R_B=\max(0.01B,1)
$$

每个时间片实际扣除：

$$
\Delta B_{\text{消耗}}=\min(B,sR_B)
$$

战争升级的战意需求：

$$
B_{\text{升级需求}}=1000+200J
$$

\(J\) 是当前战争等级。

当战意不低于需求时：

$$
\frac{dJ}{dt}=0.05
$$

当战意低于需求的一半时：

$$
\frac{dJ}{dt}=-0.2
$$

并且战争等级不能低于零。

如果战意处于这两个阈值之间，战争等级不会按上述规则持续增长或下降。

### 8. 敌人产生速度

当战争等级大于零时：

$$
Q=\max(J,1)
$$

敌人进度增加量：

$$
\boxed{
\Delta P=
\frac{\Delta B_{\text{消耗}}}{50\sqrt Q}
}
$$

每当进度累计达到 1，就生成一名新敌人，其实力基准为 \(Q\)。

因此，持续提高战意可以增加敌人出现频率，但战争等级提高后，每单位消耗战意对应的敌人进度会受到平方根因子的抑制。

### 9. 敌人遗传与进化

该系统不只是随机生成敌人，还保留被杀死敌人的基因及其战斗成绩。

敌人的基因库由两个部分构成：

* 长度最多为 5 的待继承基因列表；
* 容量受控、最多保留 50 条的种群记录。

新敌人可以从多个父代继承不同属性，然后对随机选中的一项基因做变异。

基因变异核心式为：

$$
v' = v\cdot(1+w)^{2u-1}
$$

其中 \(u\in[0,1)\) 是随机数，当前实现中的变异权重 \(w=1\)。

敌人被击杀后，其基因和功勋会参与下一轮种群筛选。功勋较高的基因更容易进入待继承集合。

因此长期战争可以改变敌人的属性分布；连续保持完全不变的防御策略，未必适合所有后续敌人。

### 10. 击杀奖励与召唤拯救

消灭敌人后得到的魔元素：

$$
\boxed{\Delta \mathrm{魔元素}=S_e}
$$

其中 \(S_e\) 是该敌人的实力值。

“召唤拯救”需要当前光明不低于 50%，发动后：

$$
J'=0,\quad B'=0,\quad
\mathrm{当前敌人列表}=\varnothing
$$

同时：

$$
L'=L-0.2
$$

这不是通常意义上的免费清场，而是消耗 20 个百分点光明，并清除当前战意和战争等级。

**使用策略：** 当敌人即将突破且现有防御无法应付时，牺牲部分光明快速清场可能比被敌人长期攻击更加划算。

战斗、敌人遗传、战争等级更新与元素恢复的逻辑均来自主脚本实际更新循环。([raw.githubusercontent.com][2], [raw.githubusercontent.com][2], [raw.githubusercontent.com][2], [raw.githubusercontent.com][2])

## 第七篇：虔诚、整洁、时间控制与隐藏机制

### 1. 虔诚感应

点击一次虔诚：

$$
\Delta D=k_{\text{虔诚感应}}^2
$$

实际膜拜倍率：

$$
\boxed{
F_{\text{虔诚}}=
1.2^{\sin(D^{1/3})\log_2(D+1)}
}
$$

\(D\) 是当前虔诚感应强度。

需要注意这不是一个单调增长的倍率。随着 \(D\) 增加，正弦函数可能由正转负，导致倍率阶段性下降，甚至低于 1。

虔诚会随着游戏时间消耗：

$$
\Delta D_{\text{消耗}}=
\min\left(
D,\,
s\max\left(
0.001D\max(1,\sqrt{F_{\text{虔诚}}}),2
\right)
\right)
$$

因此，“虔诚强度越大越好”并不是严格成立的策略。

### 2. 整洁科技的特殊计算

整洁效果取决于真诚膜拜等级的二进制因子。

设 \(v_2(a)\) 表示整数 \(a\) 的质因数分解中包含多少个因子 2，则：

$$
F_{\text{整洁}}=
1+\max\left(
v_2(a)-\frac{10}{k_{\text{整洁}}},0
\right)
$$

当整洁科技为 0 级时，该效果视为 1。

例如真诚膜拜等级为 64：

$$
64=2^6,\qquad v_2(64)=6
$$

整洁科技 2 级时：

$$
F_{\text{整洁}}=1+\max(6-5,0)=2
$$

它会改善信徒的价格指数。因此，与其随机提升真诚膜拜等级，不如结合整洁科技，主动留意某些 2 的幂次附近的等级。

### 3. 时间感应

点击一次时间感应：

$$
\Delta I=2k_{\text{时间感应}}
$$

\(I\) 是当前时间感应强度。

每个更新周期消耗：

$$
\Delta I_{\text{消耗}}=
\min\left(
I,s\max(0.01I,0.1)U_t
\right)
$$

其中 \(U_t\) 是时间不稳定系数。

世界速度增加：

$$
\Delta V=\frac{\Delta I_{\text{消耗}}}{1500}
$$

世界速度上限：

$$
\boxed{V_{\max}=1+0.2k_{\text{时间感应}}}
$$

世界速度会放大游戏更新周期中的资源生产和战斗计算。源码使用：

### 4. 时间不稳定度

游戏有一个与现实日期和分钟有关的隐藏判定。

通常：

$$
U_t=1
$$

但当：

$$
\mathrm{day}\bmod10=
\mathrm{monthIndex}\bmod9
$$

时：

$$
\boxed{
U_t=
\left(2+\frac{|\mathrm{minute}-30|}{15}\right)^{1.2}
}
$$

这里 `monthIndex` 使用 JavaScript 的月份编号：一月为 0，十二月为 11。

特殊日期下，时间不稳定系数会突然升高，使时间能量消耗、时间衰减以及时间震荡的影响增强。

这是一项真实存在的日期彩蛋，而不是剧情文本中的虚构设定。

### 5. 时间震荡

当：

$$
V>V_{\max}
$$

时会触发震荡。

代码中的震荡量含有两个随机数，可写为：

$$
Q=\min\left(
U_t\max(0.1,0.3V_{\max}r_1),
V-(0.1+0.1r_2)
\right)
$$

其中 \(r_1,r_2\in[0,1)\)。

随后：

$$
V'=V-Q
$$

当时间感应强度耗尽且世界速度高于 1 时，还存在额外自然衰减：

$$
V'=\max(1,V-0.0015sU_t)
$$

**时间系统的核心思路：** 时间感应并不是永久加速，玩家需要平衡购买时间科技消耗的世界速度、主动积累的时间能量、自然衰减和震荡损失。

相关公式位于时间感应与 `gameTick()` 更新逻辑中。([raw.githubusercontent.com][2], [raw.githubusercontent.com][2], [raw.githubusercontent.com][2])

## 第九篇：从零开始的完整通关路线

下面是一条尽量减少资源浪费、按照实际解锁顺序推进的路线。

1. **建立信仰经济**

   先进行至少 10 次点击，开放真诚膜拜；提升至 10 级开放信徒，再提升至 20 级开放教堂。建立 5 座教堂后，开始转换信仰、购买经书。

   初期的目标不是无限堆积膜拜次数，而是尽早实现信仰经济和自动点击。
2. **传教与第一批遗迹**

   通过连续答题将传教提升至一级。积累足够信徒和信仰后探索第一处遗迹，得到祈求水晶的能力。

   之后应当平衡信仰留存与水晶产量。持续清空信仰并不一定划算，因为高信仰可以明显降低祈求成本。
3. **建立三大资源产业**

   优先解锁智慧 5、奥秘 5、本质 5，并培养神坛、魔法师、科学家。

   注意每次把水晶加工成某种材料后，水晶都会被清空。建议根据即将购买的设施和即将进行的实验，决定本轮水晶用于哪种材料。
4. **通过真理 I 与真理 II**

   对所有实验建立记录。遇到高价惩罚前，要利用数学反馈筛选秘密配比。

   优先研究光学、聚焦、法术和科研支持科技，强化后续经济循环。
5. **开放外域和元素塔**

   发展几何学、法阵、烈焰阵和探索科技。开放外域后先建元素塔，形成水、火、土、风四种基本元素收入。

   在主动增加战意之前，确保防御工事拥有足够元素运行库存。
6. **持续战争与魔元素获取**

   使用水箭塔、火焰陷阱、疾风阵等工事进行防御。敌人生命值耗尽后，可通过击杀获得魔元素。

   光明过低时优先降低战争压力，不宜持续追求更高战争等级。
7. **高级研究与时间加速**

   发展真理 III 科技中的驱鸽仪、祝福术、时间感应和魔灵树。

   控制世界速度，留意时间震荡，并且在购买时间科技之前检查其所需消耗的世界速度。
8. **挑战后期真理与探索版本边界**

   真理 IV、V 的谜题仍可以研究，但第四、第五层科技内容为空；工业基地、远征和外域独立冒险均不具备完整的后续玩法。

   此时的目标更适合定义为完成已实现的系统挑战，而不是寻找源码中不存在的正式终局。

### 2. 文档 B 第一部分：零级 → 一级

这部分使用的是三维曼哈顿距离：

$$
D=|g-G|+|\ell-L|+|m-M|
$$

其中小写为玩家投入的材料数量，大写为隐藏正确值。

根据成功记录还原的三个标准答案

| 实验轮次 | 宝石 | 透镜 | 魔法石 | 猜测次数 |
| ---- | -- | -- | --- | ---- |
| 第一轮  | 15 | 15 | 15  | 3    |
| 第二轮  | 20 | 20 | 20  | 2    |
| 第三轮  | 20 | 10 | 15  | 5    |

**第一轮：**

第一次投入 `(10,10,10)`，反馈为 15；第二次投入 `(20,20,20)`，反馈也为 15。

第三次 `(15,15,15)` 刚好成功。

$$
|15-10|+|15-10|+|15-10|=15
$$

这说明第一轮答案位于三个坐标的中点。

**第二轮：**

第一次 `(10,10,10)` 的反馈为 30；第二次 `(20,20,20)` 直接成功。

$$
|10-20|\times3=30
$$

**第三轮：**

正确答案为 `(20,10,15)`。

例如使用 `(15,15,15)`：

$$
D=|15-20|+|15-10|+|15-15|=10
$$

使用 `(20,10,20)`：

$$
D=0+0+5=5
$$

最后改成 `(20,10,15)`，距离归零，实验成功。

这里透露了一个重要技巧：**保持两个材料数量不变，只调整第三种材料，可以更明确地确定目标的位置。**

### 3. 文档 B 第二部分：一级 → 二级

这一阶段采用欧几里得距离，并四舍五入：

$$
D=\operatorname{round}
\sqrt{(g-G)^2+(\ell-L)^2+(m-M)^2}
$$

三个实验的标准答案

| 实验轮次 | 宝石 | 透镜 | 魔法石 | 猜测次数 |
| ---- | -- | -- | --- | ---- |
| 第一轮  | 20 | 10 | 10  | 2    |
| 第二轮  | 15 | 15 | 15  | 3    |
| 第三轮  | 20 | 10 | 15  | 5    |

第二轮中，正确答案是 `(15,15,15)`。如果输入 `(10,10,10)`：

$$
D=\operatorname{round}\sqrt{5^2+5^2+5^2}
$$

$$
=\operatorname{round}(\sqrt{75})=9
$$

因此文档记录的反馈 9 完全正确。

第三轮答案又是 `(20,10,15)`，但与前面不同，采用欧几里得距离。输入 `(10,10,10)`：

$$
D=\operatorname{round}\sqrt{10^2+0^2+5^2}
$$

$$
=\operatorname{round}(\sqrt{125})=11
$$

这也与文件记录一致。

**结论：** 文档 B 的六组成功答案与两种距离公式是自洽的。它不只是装饰性背景文本，而是一份明确展示真理实验数学规则的教学资料。

异或计算：

| 异或结果 | 100010 = 34 |

### 5. 一个重要陷阱：相位 1 不等于成功

这是文档 E 最容易让人误解的地方。

还是使用正确答案 `(180,190,200)`。

这次玩家猜测：

$$
(185,195,200)
$$

得到：

$$
(d_x,d_y,d_z)=(5,5,0)
$$

于是：

$$
5\oplus5\oplus0=0
$$

$$
P=1
$$

但玩家猜错了两种材料！

这是因为两个相同数异或会抵消：

$$
a\oplus a=0
$$

程序实际上使用向量完全相等来判断成功：

因此：

* 相位 1：可能成功，也可能只是偏差异或后为 9 的倍数。
* 相位 2～9：肯定没有完全正确。
* 真正成功：宝石、魔法石、透镜三种材料的值全部相等。

更重要的是，**相位反馈不具有距离意义**。相位从 8 变为 2，不代表你离正确答案更近。

## 四、怎样利用文档 E 通关真理 IV？

因为隐藏目标是三个 160～220 的整数，当前网页游戏存在：

$$
61^3=\boxed{226981}
$$

种可能的正确配比。

盲目尝试不可行，尤其是游戏正常只给每阶段 9 次无额外惩罚的尝试机会。

正确的方法是根据相位筛选候选解。

下面这段 JavaScript 可以单独用于离线分析。把游戏中每次实验的材料和相位结果记录在 `history` 里，就可以得到全部仍然可能的正确答案。

使用方法是：完成一次真理 IV 实验后，记录三个投入值和反馈相位，把这条记录添加到 `history`；之后每次实验继续追加，再重新运行筛选。

当结果只有一个候选时，就可以确定隐藏答案。如果还有多个候选，则需要继续收集反馈。

注意游戏每完成一个阶段都会重新生成目标，因此**不同阶段的历史记录不能混在一起**。

这段程序只用于计算候选，不会修改游戏存档或自动提交实验。网页真实的费用与惩罚机制仍然有效。

* 游戏存档保存在 `localStorage` 中，键名为 `game-mosiyuan-save`。
* 你的加速器保存倍率所用的键名是 `mosiyuan_time_shift`。
* 游戏每隔约 20 毫秒执行一次自动存档，所以仅仅刷新页面不能清除已损坏的数值。
* 游戏将 `light` 用作界面亮度，异常数值可能导致持续黑屏；你给出的 HTML 中，背景已经是 `rgb(0, 0, 0)`。

因此，**真正需要的是删除损坏的本地存档，再重新加载游戏，而不是简单地清除 CSS、图片等网页资源缓存。** ([raw.githubusercontent.com][1], [raw.githubusercontent.com][2], [raw.githubusercontent.com][2])

// @namespace    https://lmoliver.github.io/mosiyuan/

// @description  保留最高2^512倍时间加速，增加左下角双击确认清空游戏存档的急救按钮

// @match        https://lmoliver.github.io/mosiyuan/*

(() => {
    'use strict';

    if (window.__mosiyuanTimeShiftInstalled) return;
    window.__mosiyuanTimeShiftInstalled = true;

    // 先设置急救逻辑，绝不依赖 Vue 或游戏计算是否成功。
    // 原游戏源码确定使用 localStorage['game-mosiyuan-save'] 自动保存，
    // 加速器使用 localStorage['mosiyuan_time_shift'] 保存倍率。
    const GAME_SAVE_KEY = 'game-mosiyuan-save';
    const RESET_PENDING_KEY = '__msy_emergency_reset_pending__';

    function removeSavedProgress() {
        // 只删与本游戏有关的两项，避免误删同源下其他 GitHub Pages 页面存档。
        localStorage.removeItem(GAME_SAVE_KEY);

            sessionStorage.removeItem('mosiyuan_time_shift');

    }

    // 因此刷新后的 document-start 阶段再删除一次，抢在游戏读档之前。
    try {
        if (sessionStorage.getItem(RESET_PENDING_KEY) === '1') {
            removeSavedProgress();
            sessionStorage.removeItem(RESET_PENDING_KEY);
        }
    } catch (error) {
        console.warn('[膜拜 Siyuan 急救] 重新载入时清理存档失败：', error);
    }

    function resetGame() {
        if (!window.confirm(
            '确定清空《膜拜 Siyuan》的浏览器本地存档并刷新页面吗？\n' +
            '这会永久删除游戏进度及时间加速倍率，无法撤销。\n' +
            '不会删除该域名下其他游戏的存档。'
        )) return;

        // 使用 sessionStorage 留下仅在本标签页有效的重置标记。
        // 点击确认时清理一次，下一次页面初始化时再清理一次。
        try {
            sessionStorage.setItem(RESET_PENDING_KEY, '1');
        } catch (_) {
            // 浏览器禁止 sessionStorage 时仍会尝试直接清理和刷新。
        }
        try {
            removeSavedProgress();
        } catch (error) {
            try { sessionStorage.removeItem(RESET_PENDING_KEY); } catch (_) {}
            window.alert('清除存档失败，未刷新页面。请检查浏览器的站点存储权限。\n' + error);
            return;
        }

        // 部分浏览器的离开页面过程可能允许旧存档被再次写入。

        window.addEventListener('pagehide', () => {
            try { removeSavedProgress(); } catch (_) {}
        }, { once: true });
        window.location.reload();
    }

            'cursor: pointer !important',
            'touch-action: manipulation !important',
        ].join(';');
        button.addEventListener('dblclick', resetGame);
        document.body.appendChild(button);

        // 即使游戏意外重新生成了 body 的直接子节点，也尽量重新挂回按钮。
        const observer = new MutationObserver(() => {
            if (document.body && button.parentNode !== document.body) {
                document.body.appendChild(button);
            }
        });
        observer.observe(document.body, { childList: true });
    }

    function onBodyReady(callback) {
        if (document.body) return callback();
        const observer = new MutationObserver(() => {
            if (document.body) {
                observer.disconnect();
                callback();
            }
        });

    document.head.appendChild(style);

    panel.id = 'msy-time-shift';
    panel.innerHTML = `

    const faster = panel.querySelector('#msy-faster');

        shiftLabel.textContent = `<<${shift}`;
        speedLabel.textContent = `${2 ** shift}×`;
        statusLabel.textContent = attached ? '已加速游戏时间' : '连接游戏中…';
        slower.disabled = !attached || shift === 0;
        faster.disabled = !attached || shift === MAX_SHIFT;

        if (!attached) return;
        shift = Math.max(0, Math.min(MAX_SHIFT, shift + delta));
        try {
            localStorage.setItem(SAVE_KEY, String(shift));
        } catch (_) {}
        render();
    }

    slower.addEventListener('click', () => changeShift(-1));
    faster.addEventListener('click', () => changeShift(+1));
    render();

            const vm = el.__vue__;
            if (vm &&

                typeof vm.processAchs === 'function' &&
                typeof vm.lastTime === 'number') {

        const game = findGame();
        if (!game) return;

        // 游戏主循环执行 this.gameTick(s)，其中 s 为真实经过的秒数。
        // 放大此处的时间，不改 Date.now()、世界速度或存档数据。
        const originalTick = game.gameTick;
        game.gameTick = function (seconds) {
            return originalTick.call(game, seconds * (2 ** shift));

    attach();

    });
